# Upgrading

## Requirements

| Area | Requirement | Notes |
| --- | --- | --- |
| Runtime | Python 3.10+ | Test the Python version used by production. |
| Dependencies | PyPI install | `import pure` — no build step and no autoloader to require. |
| Production | Bytecode cache (optional) | Helpful when loading generated `*.pure.py` and `*.plain.py` files. |

## Upgrade checklist

For a tagged release, update the requirement in your application and run:

```bash
pip install --upgrade purepy
```

When following the default branch, pin the tested commit in your application
instead of inventing a release number. Before deploying that commit:

1. Read the [CHANGELOG](https://github.com/YonLD/purepy/blob/main/CHANGELOG.md)
   for what changed and what a reader has to do about it.
2. Run `pure check <paths>` for component and shape units.
3. Rebuild strict and plain artifacts:

   ```bash
   pure compile <paths>
   pure compile --plain <paths>
   pure compile --check --plain <paths>
   ```

4. If the application uses `Compile.cachePath()`, remove only the cache files
   owned by Purepy when the release requires regeneration.
   `Compile.clearCache()` is the explicit API for that operation.
5. Verify the rendered output and document headers, then deploy the source and
   generated artifacts together.

Do not hand-edit `*.pure.py` or `*.plain.py`. They contain a cache-version or
shape fingerprint contract and must be regenerated by the matching compiler.

::: warning A generated artifact is checked against its compiler
A `.pure.py` file records the `CACHE_VERSION` it was built for and raises
`stale purepy artifact: generated for cache version N; run pure compile to
rebuild` when the two disagree. The plain view records a shape fingerprint the
same way. A mismatch is a deliberate failure rather than a silently wrong
document, so treat the message as the instruction it is.
:::

## Rollback

If a deployment fails, roll back the application source and its generated
artifacts as one unit. Then clear the Purepy renderer cache, rerun
`pure compile --check`, and check the first failing route. Keeping a known-good
artifact beside its source is safer than restoring only one of the two.

For symptom-specific fixes, continue with
[Troubleshooting](/guide/troubleshooting).
